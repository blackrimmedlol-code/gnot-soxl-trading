# GNOT Trading · 使用说明

## 每次交易

1. **工作台**：先选 SOXL／AGQ／LABU／MSTU，各自草稿会保留；再填真实账户权益、计划金额、计划买入价、技术止损；根据实际技术空间设置目标。核对已有持仓与新计划的合计风险预算、盈亏比。
2. **检查**：选择 Risk-on／Neutral／Risk-off，确认 9 项检查，写买入依据与重大事件评估。系统不会代替你的图形判断。
3. **保存计划**：这是计划存档，不是成交。条件未满足也可保存待执行计划，但之后的真实买入会记录未满足条件。
4. **执行日志**：打开交易轮，每笔成交填实际时间、股数、价格和理由；无需记录手续费或滑点。首笔分次成交、右侧加仓、部分减仓分别标明；重复登记会导致错误，核对券商流水。
5. **加仓前**：输入原仓盈利后的实际买入计划、趋势确认和新的合理目标，查看成交后整轮与账户合计风险。不够预算就放弃。网站没有发送订单能力。
6. **剩余仓位**：更新手动估值，记录结构止损上移。止损不能下移。实际卖出照实登记，最终清仓后另开新轮。
7. **退出后**：填写规则遵守、自我评价与复盘；统计只使用真实成交，没有预填盈利或胜率。

## 每日与每周

- 有仓位时及时更新手动价格与账户权益快照。账户权益包含现金和所有资产；四标的的单独成交盈亏不等于完整账户表现。
- 四标的合并计算连续两轮止损亏损后暂停美东当天新开仓。5% 回撤暂停并复核；10% 回撤需要系统重评，V1 不自动解除。
- 每周以及迁移设备前导出完整 JSON。浏览器隐私模式、清除数据和设备丢失都会影响本机数据。

## 数据迁移

**本机保存不等于跨设备同步。**建议指定一台主设备。JSON 和完整备份 CSV 可恢复全部字段；可读成交流水 CSV 仅供表格分析。

导入默认按 ID 合并；同一条记录在两个设备上被改动时中止，避免默默覆盖。需要整库恢复时先备份当前数据，再选择明确覆盖。更换网站域名也需要导出再导入。

最近五版本机备份只用于撤销错误，不能替代设备外的 JSON 备份。备份为明文，包含完整交易信息。

## 首版边界

初始权益 $25,000、首笔默认 $5,000、单轮及四标的持仓合计风险上限 1% 不变。任何百分比和收益目标均为制度或初始假设，未经回测验证。普通止损不保证价格，跳空可能使真实损失超过预算。SOXL／LABU 为每日三倍目标，AGQ 为白银期货每日两倍目标，MSTU 为 MSTR 单只股票每日两倍目标；多日表现并非累计收益简单乘倍数。

记录每笔实际成交价与整股数，初始 R 分母固定；导入历史备份时保留原始记账数据。

本站通过独立 GitHub 仓库与 GitHub Pages 公开托管；交易数据只保存在浏览器中，不上传到公开仓库。换域名之前从旧站导出 JSON，在新站导入并核对。

## 分标的复盘

执行日志可按标的与持仓状态筛选；表现页可选择四标的合计或单标的。账户权益快照始终涵盖完整账户，回撤不会随筛选改变。旧 SOXL 数据自动兼容，无需重新录入；交易数据仍只保存在当前浏览器。

## 2R 减半后的止损

确认实际卖出一半后，剩余止损上移至实际成本均价。交易轮的「填入保本止损参考价」只填表，须另行保存止损记录，并自行在券商确认订单。多笔买入用剩余仓位加权成本，已有更高止损不下移；之后按 30 分钟结构低点继续只向上跟踪。旧退出计划原文保留，不自动修改历史。MSTU 的旧历史记录仍不纳入主动统计，新交易另开主动轮。
